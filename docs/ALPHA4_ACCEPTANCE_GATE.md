# CERVEL Everywhere Alpha.4 Acceptance Gate

Alpha.4 release readiness is evaluated across the canonical CERVEL experience rather than through a single client or demo surface.

The gate requires evidence for:

1. Clean Mac installation and canonical Tauri build readiness.
2. Encrypted Local Node lifecycle, restart persistence, and recovery.
3. Real knowledge capture and canonical CKO persistence.
4. Life / Enterprise corpus switching without knowledge duplication.
5. Ask CERVEL with cited answers and protected Trace evidence.
6. Permission, token, provenance, and renderer trust boundaries.
7. Responsive shared experience contracts across Desktop, Web, Mobile, and Extension.
8. Local / cloud / hybrid / staging / demo deployment-mode convergence.
9. Cross-surface continuity through the CERVEL Everywhere golden path.

Release-readiness evidence is generated as a machine-readable report at `reports/alpha4/acceptance.json` and uploaded by CI. A passing gate means all automated Alpha.4 acceptance checks completed successfully. Signed release artifacts and additional physical-device qualification remain separate release controls unless explicitly included in the report.

## Acceptance principle

**One persistent knowledge substrate. One product language. Multiple embodiments. Runtime capabilities define deployment differences.**

The gate must not be satisfied by synthetic UI state alone. Runtime verification uses real encrypted Vault/Local Node paths and the existing golden-path evidence for capture, retrieval, citations, Trace, persistence, sync, revocation, and cross-surface continuity.
